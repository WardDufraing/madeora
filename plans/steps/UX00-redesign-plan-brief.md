## 2. Gaps and conflicts needing Ward (decision cards sent)

1. **D1 — Features with no binding spec: Notes (Decisions 56–61) and Work schedules (Additional requirement + Decision 43).** `CLAUDE.md`: "do not invent features"; the spec is read-only. Default if Ward does not answer: **defer both** (phases UX7 and the work-schedule slice of UX3 stay parked); everything else proceeds.
2. **D2 — Redesign vs binding spec wording.** The redesign is newer and owner-approved, but the spec still says otherwise. We need Ward to confirm the redesign supersedes, recorded in `docs/design/design-decisions.md` (not the spec files):
   - Spec L3219–L3221, L3248, L3274–L3275: only page background may have a gradient; cards "flat or very subtle elevation"; card radius 14–18, control 9–12. Redesign: pronounced tactile depth (D15), radius 12–16 / 6–10 (D16). The gradient (D21) stays page-background only, which is compliant.
   - Spec L2420: Home dashboard "shared". Redesign D33/D34: shared default **plus** optional per-member overrides.
   - Spec "independent layouts for each Household Display" (built in S44) vs D35 "one wall layout per Home, no named profiles".
     Default if unanswered: keep spec behaviour for D33–D35 and the spec token values; build only the parts that do not conflict (suggested: still do UX1–UX2 minus overrides).
3. **Not a decision, flagged:** Decision 52 priority colours are a stated exception to the single-accent rule; Decision 14 allows semantic colours. Implemented as semantic tokens (`--priority-*`), covered by the existing token-only test.
4. **Not a decision, flagged:** Decision 72 (inline shopping-item editing) is **not approved** and is out of scope (redesign doc L976).
5. **Open engineering choices (decided here, reversible, no UX change):** grid stays 12/6/1 columns with `ROW_HEIGHT` 88; named presets = Small / Medium / Large / Wide per widget derived from existing `sizes()` bounds; snap = grid cells (already true in RGL); draft storage = server row (not localStorage, per Decision 6 L35); draft conflict = reuse `revision`; motion tokens via CSS custom properties + Motion for React as CLAUDE.md already approves; widget settings save **immediately with undo toast** for quick settings and **Apply/Cancel** for the advanced side panel (flagged as a choice Ward can overrule).
6. **Sequencing vs `plans/roadmap.md`:** S49 (release readiness) is the next roadmap step. Default: UX phases run first on Ward's current priority; each is its own PR and does not block S49 work. Say so if you want S49 first.

## 5. Cross-cutting guardrails for every phase

- No change to business logic, permissions, RLS or Personal/Home boundaries unless the phase brief says so and adds multi-actor RLS tests. Personal data never rendered in Home context; previews use synthetic data.
- Layout schema stays version 1 and additive (new config fields have defaults). Caution: configs are `z.strictObject`, so an unknown key makes `readLayout` reset that widget's whole config; see section 7 for deploy order. Any new table goes in its own migration with rollback notes.
- All strings in `nl` and `en`; RTL-safe; focus returns to the trigger after every dialog; no hover-only controls.
- Copy and behaviour only from the approved decisions; anything else is raised, not guessed.

## 7. Independent review result and corrections (`reviews/steps/UX00-review.md`)

Verdict was CHANGES_REQUIRED (0 BLOCKER, 3 HIGH, 6 MEDIUM, 7 LOW). Accepted; these corrections **override** earlier text where they differ.

**HIGH**

- **Decision 37 (5-minute PIN unlock) conflicts with the built S44 rule** (migration `20261204090000_display_layouts_lock.sql` L15–17, `display-lock-dialog.tsx`: the display is unlocked only by a manager's own signed-in session; PINs are per member, and display tries never count toward a member's PIN lock). Raised to Ward as a decision. **Decision 37 stays out of UX8 until answered.**
- **Decision 36 weather** needs a provider that `Project-entry.md` L55 does not commit to MVP. Raised to Ward. Default: ambient mode **without weather** (time, date, privacy-safe items).
- **Privacy handling for every new table** (drafts, layout versions, member overrides, dismissed suggestions, favorites/recent Home, ambient/Ora/completed-display preferences). Each data phase must: add the table to the privacy export (`20261126090000_privacy_exports.sql` pattern); cascade on account and Home deletion; purge or refuse rows when a member leaves; discard or refuse a shared-default draft when `manageHomeDashboard` is revoked; use `private` schema + security-definer RPCs with grants revoked (as `dashboards.sql`); and ship multi-actor RLS/RPC tests for these cases. Draft expiry is a retention period shown to Ward in the UX2b brief, cleaned by lazy delete or a `packages/jobs` task.

**MEDIUM**

- **Compaction (Decision 5):** layout code compacts vertically everywhere (`geometry.ts`, `readLayout`, `removeWidget`, `visiblePlacements`). "Only colliding widgets move" and the hidden-widget gap policy (Decision 9) are an explicit engineering decision for UX2a/UX2b, with saved-layout stability tests; if what users see changes, ask Ward first.
- **Config strictness / rollback:** ship readers before writers; keep the `welcome` widget registered (or migrate it explicitly) when the hero header arrives; UX2a carries rollback notes.
- **"Data: none" corrected:** stored preferences are needed for hiding the Ora launcher (13), completed-task display (51), shopping grouping (68), and ambient timeout/visible content (36; `display_configs` is per display, not per Home).
