S01 (monorepo bootstrap) uses only open-source packages from the npm registry and provisions no service.

S02 (CI) uses GitHub Actions within the free quota and the open-source gitleaks CLI (MIT licence), downloaded from its GitHub release with a pinned checksum. GitHub's own secret scanning and branch protection are not free for private repositories and are not used (see `docs/github-setup.md`). A CI run uses roughly 10 to 15 billed minutes, because each of the five or six jobs is rounded up to whole minutes, so the free quota covers well over a hundred runs a month.

S03 (database) uses the open-source Supabase CLI (2.118.0, from the npm registry) to run Supabase locally in Docker, and PostgreSQL for the fallback. No hosted Supabase project is created, and tests refuse any database that is not on the local machine. The CLI sends usage statistics to PostHog unless `SUPABASE_TELEMETRY_DISABLED=1` is set; CI sets it. The CI job `Database and RLS tests` adds roughly 4 to 6 billed minutes per run (Docker image pulls and two test passes), still well within the GitHub Actions free quota. Before a hosted development project is created (S06 or later), re-check the Free plan terms above, including whether sign-up asks for a payment card; if it does, stop and ask the owner.

S04b (Vercel previews) uses the Hobby plan, which needs no card and pauses instead of charging when a limit is reached. Previews get no Supabase, R2, Resend or Trigger.dev credentials: the app has no sign-in or stored data yet. When sign-in arrives (S06), previews will need a database; the default then is a separate free Supabase project used only by previews, with synthetic seed data (Supabase's per-PR branching is paid and not used). Hobby allows non-commercial personal use only; before release (S49), the owner decides whether Madeora is commercial and therefore needs Vercel Pro or another host.

S06 (accounts) adds one hosted Supabase project, `madeora-preview`, on the Free plan (owner guide: `docs/supabase-preview-setup.md`, ADR 0007). It is used only by Vercel previews and holds synthetic accounts only; previews get its public URL and publishable key, never a secret key. Development and CI keep using the local stack. Paid features stay off: leaked-password protection, custom SMTP on a paid provider and per-PR branching. Supabase only allows custom email templates with custom SMTP, so the preview project sends through Resend's free SMTP (see the Resend row): without a domain, only from `onboarding@resend.dev` to the owner's own address. No domain is bought (€0) at S06. The app's own Resend integration is S10. The project pauses after a week without use and is restored from the dashboard at no cost. The second free project slot stays unused, for staging later. If Supabase asks for a card at sign-up or project creation, stop and ask the owner.

S06b (early production, ADR 0008) adds a second free Supabase project, `madeora-production`, so both free project slots are now in use; staging (S49) will need one paused or a paid plan. Production holds demo accounts only, keeps sign-up closed until S10, sends email through a separate Resend API key (still only to the owner without a domain), and uses a free Cloudflare Turnstile widget whose secret key lives only in Supabase. Vercel production deploys stay on Hobby: free, no card, non-commercial use only. Owner guide: `docs/production-setup.md`.

The domain `madeora.studio` is the first paid item. The owner registered it (about €20 a year, 2026-10-14), so it is owner-approved spend outside the €0 development budget; the registrar and renewal date are kept by the owner. Vercel serves it on the free Hobby plan.

S08 (Google sign-in, ADR 0010) adds a Google Cloud project with one OAuth web client per Supabase project. Basic sign-in with `openid`, `email` and `profile` costs nothing and needs no billing account; the owner leaves the Google free trial unstarted. The client secrets live only in Supabase. CI never contacts Google: the new job "E2E Google sign-in" builds the pinned Supabase Auth and Mailpit from source with Go, downloads PostgREST once per run (checksum pinned) and uses a local stand-in for Google, adding roughly 6 to 10 billed minutes per run, within the GitHub Actions free quota.
